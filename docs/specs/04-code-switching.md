# 04 · 中英混读 Code-Switching

> 维度编号：CODE-SWITCH | 优先级：P0

## 背景

国内开发者/科技从业者说话天然夹杂英文："我部署在 AWS 上，用 Lambda 跑个 cron job"。这是中文 ASR 的真实高频痛点，也是 Whisper 中文场景的常见翻车点——经常把中文词翻译成英文，或把英文词音译成中文。

## 测试集要求

- **音频数量**：≥ 30 条
- **说话人**：至少 3 人，能自然中英混说（科技从业者最佳）
- **混读类型覆盖**：
  - 技术术语："用 Docker 部署，CI/CD 跑通了"
  - 产品名："我今天买了个 iPhone 15 Pro"
  - 中英短语交替："这个 feature 我觉得可以 ship 了"
  - 数字+单位混读："响应时间在 200ms 以内"
  - 人名/地名："明天和 John 开会"
- **不允许**：整句英文（那是 spec 03），必须是中文为主夹杂英文
- **参考转写**：保留原文的中英混排形式

## 评测指标

| 指标 | 说明 |
| --- | --- |
| 混合 CER | 按字符切分（中英统一按字） |
| **英文词准确率** | 单独统计英文部分是否被正确识别为英文，还是被音译成中文 |
| 语言切换正确率 | 模型是否在该说英文的地方说了英文 |
| 误翻译率 | 中文被翻译成英文、或英文被音译成中文的比例 |

## 特别观察项

- Whisper 常见问题：把"Docker"识别成"道客"或"码头"
- SenseVoice 预设语言可能强制中文模式，导致英文词被强行中文化
- Qwen3-ASR 的 52 语言支持预期在这个维度有优势

## 注意事项

- 这个维度的参考转写必须**保留说话人实际说的英文**，不要把"iPhone"改成"苹果手机"
- 归一化时不要把英文词自动翻译成中文
- 单独统计"英文词数"作为分母，避免中文部分拉低整体指标
