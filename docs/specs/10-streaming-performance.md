# 10 · 流式实时性与工程性能

> 维度编号：STREAMING-PERF | 优先级：P0

## 背景

用户明确要求"需要流式 ASR、离线转写，项目需要区分场景"。这个维度覆盖工程层面的所有指标：流式首字延迟、RTF、内存、加载时间、长音频分段。这是选模型时和准确率同等重要的决策依据。

## 评测内容

### 10.1 流式首字延迟（TTFB）

- **定义**：从喂入第一个音频帧到输出第一个非空字符的毫秒数
- **测试方法**：用预录音频模拟实时流，按 chunk（默认 300ms）逐帧喂入，记录每帧后是否有新文本输出
- **测试模型**：仅支持流式的模型（Qwen3-ASR 系列）
- **指标**：
  - 首字延迟中位数
  - 不同 chunk 大小（100ms / 300ms / 500ms）下的延迟与准确率权衡
  - 流式过程中是否出现"先错后改"的文本抖动

### 10.2 离线 RTF（实时率）

- **定义**：转写耗时 / 音频时长
- **测试方法**：同 spec 02/03 的干净音频，跑每个模型
- **指标**：
  - RTF 中位数（越低越快）
  - 长音频（> 60s）vs 短音频（< 5s）的 RTF 差异
  - 首次加载时间（模型权重加载到内存）

### 10.3 内存占用

- **指标**：
  - 模型加载后常驻 RSS
  - 转写期间 RSS 峰值
  - 长音频（10 分钟）下内存是否线性增长
- **采样方式**：与 TTS arena 一致，每 50ms 采样进程树 RSS

### 10.4 长音频处理

- **测试音频**：1 分钟 / 5 分钟 / 10 分钟的连续语音
- **观察项**：
  - 是否自动分段（VAD）
  - 长音频下是否出现重复输出（ hallucination loop）
  - 是否有最大时长限制
  - 10 分钟音频的总转写时间

### 10.5 模型体积与加载

| 指标 | 说明 |
| --- | --- |
| 权重文件大小 | GB |
| 首次加载时间 | 从启动到可接收音频的秒数 |
| 冷启动 vs 热启动 | 第二次加载是否有缓存优势 |

## 评测指标汇总

| 指标 | 单位 | 说明 |
| --- | --- | --- |
| first_token_ms | ms | 流式首字延迟 |
| chunk_interval_ms | ms | 流式更新间隔 |
| rtf | 倍 | 离线转写速度（< 1 比实时快） |
| load_time_ms | ms | 模型加载时间 |
| memory_peak_mb | MB | RSS 峰值 |
| memory_idle_mb | MB | 空闲常驻内存 |
| long_audio_10min_ok | bool | 10 分钟音频是否完整转写 |

## 特别观察项

- Qwen3-ASR 统一流式/离线路径，实测流式延迟是否可接受（目标 < 500ms）
- Whisper 系列本质是离线模型，不支持真流式；若通过"滑动窗口"模拟流式，首字延迟等于一整个窗口时长
- SenseVoice/Paraformer 在 CPU 上的 RTF 优势（FunASR 宣称 20× 实时）
- 内存占用：1.7B Qwen3-ASR vs 809M Whisper turbo vs 234M SenseVoice

## 注意事项

- RTF 数字来自 datacenter 硬件的数字不能直接搬到 Mac 上，必须实测
- 流式评测要和离线评测用同一批音频，才能对比"流式延迟换来了多少准确率损失"
- 内存指标是进程 RSS，不等于显存/MPS 内存，要在文档里说明口径
- 不要把"RTF < 1"等同于"可以做实时语音助手"——还要看首字延迟和 VAD 行为
- 加载时间只测一次，不重复进中位数
