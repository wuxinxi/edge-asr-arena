# 评测平台总体设计

[返回 README](../README.md) · [架构设计](architecture.md) · [模型选型](models.md)

本文档定义 edge-asr-arena 的指标口径、批次管理、对比界面和历史管理规则。与 TTS arena 对齐，但质量判断从主观听感转为客观 CER/WER。

## 配置与场景

统一条件使用相同音频和基础预设。所有模型以相同采样率（16kHz 单声道 WAV）输入，不做额外前端处理；VAD 分段策略各模型保持默认，不统一替换。

测试集按 10 个维度组织，见 [specs/](specs/)。每条音频在 `testset/manifest.json` 中记录：文件路径、参考转写文本、语言、SNR、场景标签、说话人 ID、时长。结果按维度分别查看，避免把干净音频和噪声音频混合排名。

模型能力不兼容时自动不可选：例如选择"英文"维度时，Paraformer（中文为主）应自动取消勾选并提示原因；选择"流式"模式时，不支持流式的模型不可选。切换到兼容维度后恢复可选，但不自动重新勾选。

## 指标计算

| 字段 | 实际计算 |
| --- | --- |
| `cer` | 中文按字（字符）计算错误率：(S+D+I) / N_ref_chars |
| `wer` | 英文按词计算错误率：(S+D+I) / N_ref_words |
| `substitutions` | 替换错误数 |
| `deletions` | 删除错误数（漏字） |
| `insertions` | 插入错误数（幻觉/多字） |
| `elapsed_ms` | 从喂入音频到拿到完整转写的总耗时（离线） |
| `rtf` | `elapsed_ms / audio_duration_ms`，越小越快 |
| `first_token_ms` | 流式场景：从首个音频帧到首个输出字符的延迟 |
| `memory_peak_mb` | 后端进程树 RSS 峰值（字节/1024²） |
| `memory_diff_mb` | `max(0, peak - 运行前基线)` |

### 文本归一化（先于 CER/WER 计算）

不同模型输出格式差异大，必须先归一化再比对：

- 全角数字/字母 → 半角（"３点" → "3点"）
- 中文标点与英文标点统一为一种（默认统一为中文标点）
- 去除首尾空白、合并连续空格
- 英文大小写统一为小写后比对（同时保留原始输出展示）
- 数字写法归一化："三点" → "3点"（可配置开关）
- 去除语气词？**默认不去除**，因为"嗯/啊"是否算错误取决于场景；在 spec 01 中定义

归一化规则本身作为一个评测维度（spec 01），不同规则会显著影响 CER 数值。

## 重复统计与图表

每条音频按模型汇总成功/失败次数、CER 中位数和范围、RTF 中位数、RSS 增量中位数。API 支持 1–5 次重复，界面提供 1/2/3/5 次。

- 失败不进入指标统计，缺失指标不填零。
- 已返回的失败项计入成功率分母；排队、未运行项不计入。
- 多次重复的 CER 范围反映运行波动，不反映模型在不同音频上的方差。
- 人工校验结果（用户标注某条转写是否可接受）单独保存，不自动改写 CER。

默认柱状图按所选指标中位数从低到高排列。折线图横轴按模型参数量排列。

性能雷达最多叠加四款模型，四轴为：RTF、内存峰值、首字延迟（流式）、CER。相对值为「本轮最低值 / 当前值 × 100」，越向外代价越低。**雷达面积不能作为综合能力分**，原始数据与单位始终是判断依据。

## 转写对比（A/B）

总览中选择同一音频的两个模型转写结果并排展示：
- 原始音频可播放
- 转写文本逐字高亮：绿色=匹配，红色=替换，删除线=参考有但输出漏了，下划线=输出多了
- 差异字词一键跳转
- 人工校验区：可标注"该错误可接受/不可接受"，保存到 `.review.json`

## 批次状态与操作

任务按「模型 × 音频 × 次数」串行执行，平台与 CLI 共用推理锁。进度表示已返回结果的任务比例，不是模型内部推理百分比。

- 停止仅阻止后续任务，当前转写会正常结束并保存。
- 重试只针对原失败项，创建关联新批次，保留原样本与次数，不覆盖旧结果。
- 刷新页面尝试恢复活动任务；服务重启后未结束任务标为中断，不自动继续。
- 查看历史结果不恢复待运行计划，点击"使用这些条件"才恢复配置。

## 流式评测专项

流式模式与离线模式分开记录：

- **首字延迟 (TTFB)**：从开始喂音频到第一个非空输出字符的毫秒数
- **段间间隔**：流式转写过程中两次更新之间的间隔
- **最终 CER**：流式结束后的完整文本与参考对齐
- **流式稳定性**：过程中是否出现"先输出错误文本后又修正"的抖动（可配置是否记录中间态）

不支持流式的模型在流式批次中自动不可选。流式 chunk 大小（默认 100ms/300ms）和延迟策略作为批次参数记录。

## 历史分页与回收站

与 TTS arena 一致：
- **批次历史**：删除状态保存于批次快照，运行中/排队中不可删除
- **单条转写历史**：独立保存，仅隐藏列表记录，原音频、转写文本、指标仍可用
- 两者均保留原音频和参数，不提供永久清空

## 批次 API

```bash
# 创建离线评测批次
curl -X POST http://127.0.0.1:8082/api/asr/compare/jobs \
  -H 'Content-Type: application/json' \
  -d '{
    "model_keys": ["whisper-turbo", "qwen3-asr-0.6b", "sensevoice-small"],
    "dimension": "06-noise",
    "testset_filter": {"snr": [5, 10, 20]},
    "mode": "offline",
    "repeats": 1
  }'

# 创建流式评测批次
curl -X POST http://127.0.0.1:8082/api/asr/compare/jobs \
  -H 'Content-Type: application/json' \
  -d '{
    "model_keys": ["qwen3-asr-0.6b"],
    "dimension": "09-emotion",
    "mode": "streaming",
    "chunk_ms": 300,
    "repeats": 1
  }'
```

| --- | --- |
| 硬件/模型状态 | `GET /api/system`、`GET /api/models` |
| 测试集维度列表 | `GET /api/testset/dimensions` |
| 测试集音频列表 | `GET /api/testset/{dimension}` |
| 创建批次 | `POST /api/asr/compare/jobs` |

## 与 TTS arena 的差异总结

| 项 | TTS arena | ASR arena |
| --- | --- | --- |
| 输入 | 文本 | 音频文件 |
| 输出 | 音频 | 转写文本 |
| 质量指标 | 人工听感 | **CER/WER 自动计算** |
| 对比方式 | A/B 听音频 | A/B 对比转写文本+差异高亮 |
| 流式 | 未测 | **首字延迟为核心指标** |
| 测试集 | 内置文本 | 自录音频+参考转写 manifest |
| 主观记录 | 自然度/表达/杂音 | 幻觉/漏字/错词/可接受性 |
